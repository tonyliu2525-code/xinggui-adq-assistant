# 1. 新投放营销MKTAPI3.0概述



新版3.0腾讯营销投放平台，进行了投放的重新设计，以更精简高效的投放体验支持完整的营销内容表达。并且进行系统全面升级，以更稳定的系统优化，打破“卷基建”的起量玄学。



新版本功能包括：



· 投放层级精简，由原有的“计划-营销-创意”3层结构简化为“营销-创意”2层结构



· 贴近行业经营的投放表达，通过营销目的代替推广目标，更精细化刻画行业的生意经营



· 明确投放导向，新建营销环节增加“卷基建”判断，杜绝无序创建，聚合转化数据以提升拿量效果



为适配新投放场景，MKTAPI升级为3.0版本，支持开发者更容易、更便捷地进行营销创编和资产管理，主要核心升级点如下：

**1. 营销内容**



营销内容主要包含四部分，分别为**营销目的（MARKETING_GOAL）、营销载体（MARKETING_CARRIER_TYPE）、推广内容（MARKETING_ASSET_ID）、优化目标（OPTIMIZATIONGOAL）**，以下分别介绍如何通过 **MKTAPI 创建/获取**上述四种营销内容：



| 营销内容 | 字段 | 介绍 |

| -------- | -------- | -------- |

| 营销目的 | MARKETING_GOAL | 用于表达客户实际的投放目的 |

| 营销载体 | MARKETING_CARRIER_TYPE | 营销载体是推广产品的承载方，是落地页类型的聚类，是需要归因数据和触达的中间载体 |

| 推广内容 | MARKETING_TARGET_TYPE（推广内容类型）
MARKETING_ASSET_ID（推广产品id） | 推广内容类型：是指本次投放推广的标的物类型，如应用、商品、服务、活动等
推广产品ID：是指本次投放推广的标的物具体的 ID，入商品 id、应用 id 等 |

| 优化目标 | OPTIMIZATIONGOAL | 优化目标是指本次投放要优化的转化动作，如关注、下单、付费、线索收集等 |

**（3）推广内容**



推广内容包括推广内容类型（MARKETING_TARGET_TYPE）和推广产品ID（MARKETING_ASSET_ID），定义如下：



➢ 推广内容类型：是指本次投放推广的标的物类型，如应用、商品、服务、活动等



➢ 推广产品ID：是指本次投放推广的标的物具体的 ID，入商品 id、应用 id 等



**推广内容资产的获取通过下面方式实现：**



➢ 创建营销时，可通过**获取可投放推广内容资产类型名称（marketing_target_types/get）** 接口查询可投放的推广内容类型、可通过**获取可投放推广内容资产相关信息（marketing_target_assets/get）** 接口查询可投放的**推广产品id（MARKETING_ASSET_ID）** 以及所属的产品属性，注意：**推广内容资产相关信息（marketing_target_assets/get）** 接口仅支持查询非通用类资产



➢ **通用类资产（app、小程序、小游戏、视频号、公众号、商品等）** 通过 adgroup 创建时**marketing_asset_outer_spec** 表达



注：推广内容类型（MARKETING_TARGET_TYPE）为 电商商品（MARKETING_TARGET_TYPE_CONSUMER_PRODUCT）时，marketing_asset_outer_spec 通过 获取商品库接口（product_catalogs/get）&获取商品接口（product_items/get）获取对应商品库 id（product_catalog_id） 和商品 id（product_outer_id）

4.1 出价



通过[开发者文档 | 开发者专区 - 腾讯营销](https://developers.e.qq.com/v3.0/docs/enums)获取出价方式、策略等枚举值进行投放

营销的出价由优化目标（optimization_goal）、扣费方式（bid_mode）和 出价金额（bid_amount）共同决定。 Marketing API 当前支持多种优化目标，不同的优化目标可选择的出价方式不同，两者的对应关系如下所示：



|	组合	|	说明	|

|	BILLINGEVENT_APP_DOWNLOAD + OPTIMIZATIONGOAL_APP_DOWNLOAD	|	CPA（按下载完成计费）	|

|	BILLINGEVENT_CLICK/BILLINGEVENT_IMPRESSION + 以下优化目标：OPTIMIZATIONGOAL_APP_ACTIVATE,
OPTIMIZATIONGOAL_APP_REGISTER,OPTIMIZATIONGOAL_PROMOTION_CLICK_KEY_PAGE,
OPTIMIZATIONGOAL_ECOMMERCE_ORDER,
OPTIMIZATIONGOAL_APP_PURCHASE,
OPTIMIZATIONGOAL_ECOMMERCE_CHECKOUT,OPTIMIZATIONGOAL_PAGE_RESERVATION,
…oCPA目前支持的优化目标可通过
[开发文档 开发者专区 - 腾讯营销](https://developers.e.qq.com/docs/guide/ads/ocpa)进一步了解	|	oCPA（基于效果的自动优化计费）	|



选择营销的出价方式后，您还需要设置营销的具体出价金额（bid_amount），且您在创建或修改营销的时候出价必须符合限制，否则会报错，具体的出价限制如下：



1. CPC出价限制：介于10分-10,000分之间（0.1元-100元，单位为人民币）



2. CPM出价限制：介于150分-99,900之间（1.5元-999元，单位为人民币）



3. CPA出价限制：介于100分-10,000分之间（1元-100元，单位为人民币）



4. oCPC/oCPM 出价限制：介于 10 分-500,000 分之间（0.1 元-5000 元，单位为人民币）

## 2.2 如何接入

### 2.2.1 接口路径、授权、频控的变化

（1）接口路径：3.0 API的接口路径前缀升级为/v3.0/



（2）OAuth2.0 授权：相比于老的API，整个授权流程没有变化。可以授权的账户类型中，商务管家概念后续会下线（下线后不再支持新的授权），取而代之的是新的组织概念，建议开发者引导商务管家的授权切换到组织的授权。



（3）当前应用如何访问3.0 API接口：目前接入中的应用（client_id），已经全部自动升级到3.0版本新应用（具体升级方式参见详细的升级指引），可以同时访问3.0 API接口和老的API接口，不需要额外申请权限。



（4）频控策略：3.0接口的频控策略和之前保持不变，和老接口的频控统一计算。例如：开发者官网上应用A在adgroups/get接口的频控是1000qpm，可以用700qpm访问v3.0/adgroups/get，用300qpm访问v1.3/adgroups/get，要求这两个接口的总的访问频次在1000qpm以内。



### 2.2.2 技术层面其他关键变更

（1）GET请求参数仅支持这一种传入方式：需要对非string类型的参数的值进行json序列化再传入



（2）POST请求，对于非文件上传类接口，仅支持Content-Type为application/json；对于文件上传类接口，仅支持Content-Type为multipart/form-data



（3）对于接口参数的类型要求会更加严格，例如老版本API的get接口中，filtering的values是[]string类型，但是如果传入int类型，也能请求成功；新版本中这类请求会报错，请严格按照文档中的字段类型进行传入。



（4）请使用UTF8编码，不再支持GBK编码



（5）接口提供更加清晰的错误码和错误消息



（6）/v3.0/的接口必须使用https



（7）不再提供沙箱环境 



（8）微信公众平台账户暂时不支持

# 4.常见 Q&A

**问题 1：为什么报接口调用次数超限错误或者Application request limit has been exceeded？**



答：系统对每个应用程序（client_id）每个接口的调用有每天总量和每分钟频次的限制。默认情况下，新开通的应用每天总量限制为读接口20000次/接口，写接口10000次/接口。每分钟的频次均为1000次/接口，请检查您的调用是否超限。如果您发现默认的限制不符合您业务的需要，可联系接口的运营人员，我们会根据实际情况酌情调整。更多返回码详细说明参见https://developers.e.qq.com/docs/reference/errorcode页面介绍



**问题 2：MKTAPI3.0 是否支持老 BM 授权**



答：不支持，MKTAPI3.0 新管理能力升级，v3.0 接口支持集团/主体/业务单元/客户账户进行授权，不再支持老 BM 授权，注：老 v1.3 接口还支持老 BM 授权；



**问题3：老 MP 账户是否通过 MKTAPI可投放 3.0 营销？**



答：老 MP 账户不支持通过 API 投放 3.0 营销，建议申请 ADQ 账户进行投放。
